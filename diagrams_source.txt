Този файл съдържа изходния код на всички диаграми, отбелязани в документацията
с placeholder-и <diagram for ...>.

СЪДЪРЖАНИЕ
  ЧАСТ 1 — draw.io (структурни диаграми) ...... 6 диаграми, 1 .drawio файл с 6 страници
  ЧАСТ 2 — sequencediagram.org (sequence) ..... 4 + 1 бонус диаграми

--------------------------------------------------------------------------------
 КАК ДА ГИ ИЗПОЛЗВАТЕ
--------------------------------------------------------------------------------
draw.io  (app.diagrams.net или desktop):
  Вариант А: Копирайте целия блок между маркерите
             [DRAWIO-FILE-START] ... [DRAWIO-FILE-END] в нов файл "diagrams.drawio"
             и го отворете — всяка диаграма е на отделна страница (таб долу).
  Вариант Б: За една диаграма: File ▸ New ▸ Blank ▸ Extras ▸ Edit Diagram…,
             поставете съответния <mxGraphModel>…</mxGraphModel> и натиснете OK.
  След отваряне може да подредите автоматично: Arrange ▸ Layout (напр. Tree / Organic).

sequencediagram.org:
  Отворете https://sequencediagram.org/ , изтрийте примера вляво и поставете
  съответния блок (между --- BEGIN --- и --- END ---). Export: PNG/SVG.

title 3.1.3 Качване на файл (File Upload)

actor "Потребител (Browser)" as U

deactivate FC

 2-B) 3.1.5  Споделяне чрез токен (sharing token flow diagram)
--------------------------------------------------------------------------------
--- BEGIN ---
title 3.1.5 Споделяне чрез токен (Sharing Token Flow)

actor "Собственик" as O
participant "ShareController" as SC
participant "ShareService" as SS
participant "TokenUtil" as TU
database "MySQL\n(shared_items)" as DB
actor "Получател" as R
participant "PublicShareController" as PC

group Създаване на споделяне
O->SC: POST /api/shares\n(itemId, itemType, permission, expiresAt)
SC->SS: create(req, owner)
SS->TU: newOpaqueToken()  // 32 random bytes
TU-->SS: rawToken
SS->TU: sha256Hex(rawToken)
TU-->SS: tokenHash
SS->DB: save(SharedItem{ tokenHash, ... })
note over DB: Пази се само SHA-256 хешът —\nraw токенът никога не се записва
DB-->SS: saved
SS-->SC: ShareCreateResponse(rawToken)
SC-->O: 200 OK + rawToken (показва се еднократно)
end

group Достъп до споделена връзка
R->PC: GET /public/shares/{rawToken}
PC->SS: sha256Hex(rawToken) -> tokenHash
SS->DB: findByTokenHash(tokenHash)
DB-->SS: SharedItem
SS->SS: проверка: revokedAt == null\nи expiresAt не е изтекъл
SS-->PC: ShareInfoResponse
PC-->R: 200 OK (тип, ниво на достъп, изтичане)
end
--- END ---

 2-D) 3.5.2  eIDAS PAdES-B-B подписване (eIDAS PDF signing flow)
--------------------------------------------------------------------------------
--- BEGIN ---
title 3.5.2 PAdES-B-B подписване (eIDAS)

actor "Потребител" as U
participant "DocumentSigningController" as DC
participant "DocumentSigningService" as DS
participant "PKCS#12 Keystore\n(.p12)" as KS
participant "PDFBox + BouncyCastle" as LIB
participant "Файлова система" as DISK
database "MySQL\n(document_signatures)" as DB

U->DC: POST /api/signatures/files/{fileId}/sign
activate DC
DC->DS: signPdf(fileId, user)
activate DS
DS->KS: зареждане на private key + X.509 сертификат
KS-->DS: privateKey, certChain
DS->LIB: Loader.loadPDF(source)
DS->LIB: addSignature(PDSignature\nFILTER_ADOBE_PPKLITE / PKCS7_DETACHED)
DS->LIB: CMS подпис — SHA256withRSA (PKCS#7 detached)
LIB-->DS: подписани байтове
DS->DISK: saveIncremental -> signed_{uuid}.pdf
DISK-->DS: OK
DS->DB: save(DocumentSignature — метаданни)
DB-->DS: saved
DS-->DC: SignatureResponse
deactivate DS
DC-->U: 200 OK\n(signerName, Subject/Issuer, signedAt, PAdES-B-B)
deactivate DC
--- END ---

--------------------------------------------------------------------------------
 2-E) (Бонус) 2.5  JWT автентикация — Login + Refresh rotation
--------------------------------------------------------------------------------
--- BEGIN ---
title 2.5 JWT автентикация (Login + Refresh)

actor "Потребител" as U
participant "AuthController" as AC
participant "AuthService" as AS
participant "AuthenticationManager\n+ BCrypt" as AM
participant "JwtService" as JS
database "MySQL\n(refresh_tokens)" as DB

group Вход (Login)
U->AC: POST /api/auth/login\n(username/email, password)
AC->AS: login(req)
AS->AM: authenticate(credentials)
AM-->AS: Authentication OK
AS->JS: издаване на access token (JWT, HS256, 1 час)
JS-->AS: accessToken
AS->DB: save refresh token (SHA-256 hash, 30 дни)
AS-->AC: AuthTokensResponse(access, refresh)
AC-->U: 200 OK (access + refresh)
end

group Опресняване (Refresh / rotation)
U->AC: POST /api/auth/refresh (refreshToken)
AC->AS: refresh(req)
AS->DB: проверка на tokenHash (валиден, не е оттеглен)
DB-->AS: OK -> анулиране на стария токен
AS->JS: нов access token
AS->DB: нов refresh token (rotation)
AS-->AC: нов AuthTokensResponse
AC-->U: 200 OK (нов чифт токени)
end
--- END ---
